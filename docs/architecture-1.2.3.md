基线为主分支提交 `bb127914c71043f05be28964e94e2ee9fc8b36b0`。本轮沿用 1.2.2、Android 版本码 25、原包名、Windows Upgrade UUID 和 Android 签名。文件名沿用工程需求书的文档编号。公开下载继续指向 v1.2.1。

## 设备发现和身份核验

Windows 并行查询 Rust mDNS、官方 ADB mDNS 和应用专用服务的连接列表。Android 同时使用 Rust mDNS、短时多播锁和 NSD。每个来源提交自己的最新快照，新增、移除和地址变化会更新合并结果。去重键包含实例名、服务类型和完整端点。具有不同网络作用域的 IPv6 地址、同一实例的多个候选地址和配对端口均可保留。已连接端点有具名记录时隐藏无名重复项。

单个查询预算为 6 秒，同一主控的并发订阅共享一次查询。最后一个订阅取消后关闭扫描，下一轮会等待上一轮监听清理。Rust 服务复用一个守护实例，缓存过期时间 120 秒，空闲 8 秒后退出。Android 在结束扫描和进入后台时释放多播锁及监听器。API 33 及以上的 NSD 事件按网络分别管理，API 34 及以上读取多个主机地址。早期 Android 的 NSD API 仅返回一个地址，Rust 可补充其他候选地址。发现结果只用于定位，每次业务重连继续校验原设备身份。

## Windows 并发和工具管理

| 阻塞任务 | 全局并行上限 |
| --- | ---: |
| 外部命令 | 8 |
| 外部命令 stdout / stderr 读取 | 16 |
| 普通业务命令 | 12 |
| 文件传输、持续日志 | 8 |
| 控制及探活 | 6 |
| 设备状态订阅 | 32 |
| 镜像进程输出 | 2 |

线程按需创建，空闲 10 秒后回收。各池直接交接工作，不积压等待队列。每台设备另限 6 个普通命令和 3 条长流。达到上限会返回错误码 10。取消外部命令可直接销毁其子进程，取消套接字或原生流无需等待工作线程。诊断快照提供线程、排队数、会话、流、子进程、通道和累计拒绝数。当前排队数在直接交接机制下为零。重复打开运行中的镜像通过已有窗口 PID 激活。

自选 ADB 检查无线配对参数、transport ID、`-L`、`--one-device`，再用用户态回环动态端口运行前台服务，读取有效的 `host:track-devices-l` 初始帧。探测结束关闭这个子进程。工具缓存键包括路径、长度、修改时间及配对要求。旧工具被替换后会重新验证。回退原因可在设置页查看。官方 Scrcpy 与其配套 Server 继续随 MSI 安装，Android 保留 AndroidKeyStore 和兼容连接以使用原有密钥。

## 日志内存与消费游标

最多同时存在 32 个采集器，每个预留 1 MiB 总预算。原生端计入记录队列容量、字符串分配容量、64 KiB 输入块、16 KiB 未完行、临时转换空间以及最大序列化页。固定份额使一个产生异常长日志的设备不能挤占其他设备。每个采集器最多 1,500 条，单行上限为 16 KiB 原始输入和 4,096 个 UTF-16 单元（包含截断标记）。分配器元数据、虚拟机和系统工具的开销另计。

每页最多 256 条且不超过 256 KiB，包含本页结束序号、累计淘汰数、最新序号。最旧可读取序号等于累计淘汰数加一。Kotlin 只确认本次收到的页，后台解码，在页间让出主线程。新游标落后于淘汰边界时单独统计未读损失。暂停显示和导出使用点击时可见的过滤结果。离线工作区接管尚待消费的末页并释放已读完的原生采集器。清空、重新采集和旧回调通过句柄和代次隔离。

## 恢复和资源所有权

| 错误码 | 行为 |
| --- | --- |
| 1 Timeout | 探活有限次复核，连续三轮重连尝试失败后提示手动连接 |
| 2 Network | 退避，网络变化可提前唤醒并重新发现端点 |
| 3 Refused | 查找同一服务的其他候选端点，逐个验证 |
| 4 Authentication、5 Identity | 停止恢复，提示核对授权或设备身份 |
| 6 Closed | 以当前会话已验证身份重新连接 |
| 7 Protocol | 普通操作报错，探活或重连协议不兼容时停止该会话 |
| 8 Cancelled | 结束当前操作，不累计探活失败 |
| 9 Backend | 按需恢复兼容服务，原生 TLS 与镜像兼容服务独立 |
| 10 Exhausted | 控制通道保留容量，短暂等待资源，不计入探活失败 |

Rust reader pump 将稳定错误码和底层诊断一起传给 Kotlin。会话不再保留未使用的端点字符串。传输代次防止旧关闭事件释放新设备，定时任务在回调执行前再次核对票据。共享 Tokio 的两个工作线程处理异步 I/O，阻塞 JNI 回调使用独立、最多四线程的阻塞池。恢复后只继续探活和用户已申请的日志，安装、覆盖、删除等写操作继续保留待核实状态。

## 构建及验证

Windows x64 本机，JDK 17、Rust 1.100、Android NDK r27c。使用授权的 Android 11 RK3566 和隔离的 Android x86_64 模拟器。测试时只更换测试主控和模拟器的 QA 配置。发行候选包通过 Gradle `:app:packageMsi :app:assembleRelease -PrprobeAbiApks=true` 构建。使用原证书签名通用、arm64-v8a、armeabi-v7a、x86 和 x86_64 五个 APK。检查每个 APK 的证书、包名、版本、ABI、16 KiB ZIP 及 ELF LOAD 对齐。无需新增依赖和第三方许可。

GitHub Actions 的只读工作流在 Windows 和 Linux 执行 Rustfmt、Clippy 和全部 Rust 单测。Android 编译、签名以及需要设备、私有桌面或安装器的项目在本机验证。复现 Windows/Android 构建所需的本地工具和参数见[上一阶段构建记录](architecture-1.2.2.md)。

### 自动化和设备回归

- Rust 格式检查、Clippy（警告视为失败）和 13 项单元测试通过。覆盖 32 路长日志、UTF-8 分块、异常长行、淘汰、分页、传输错误码和会话状态。
- 桌面测试集共 95 项。最终普通回归执行 87 项，另外 8 项按显式设备或配对条件分组执行。专用组覆盖两台设备切换、32 MiB 文件完整性与取消、单设备长流占满后的探活和其他设备、端点变更、adbd 重启及真实 TLS 配对。在测试器等候配对码超时后，重新通过 QA 模拟器设置页获取一次性配对码，独立运行的 Windows 配对与重连测试通过。临时设置窗口和动态端口均属于测试实例。
- 并发回归验证了同时写满子进程两条输出管道、取消阻塞操作、10 秒空闲回收、满额时拒绝新流和保留控制通道。32 个日志句柄全部占用时，工作区能提示容量不足。归还句柄后重新采集、清空和再接收均通过。
- Android 七项功能测试覆盖发现、启动、Shell、文件及截图、测试 APK 安装/卸载、日志、系统选择器和镜像返回。初次运行的镜像用例遇到一次兼容流关闭。整组重跑和最终 APK 对应代码的七项回归均通过。独立 HTTPS 安装和无线配对故障测试也通过。故障组实际切换 Wi-Fi、重启无线调试并在新的 TLS 端口恢复，在 40 ms 延迟和 2% 模拟丢包下复核已授权连接。
- Windows 自选工具的原生文件选择器、替换后的旧版 ADB、内置回退诊断、Scrcpy 渲染和输入控制均经过测试。RK3566 连续 123 秒保持一个会话，Shell、监控和 Logcat 三轮采样均通过。另行验证横竖屏切换后的镜像画面和镜像关闭后的原会话。
- 正式签名的 x86_64 APK 和通用 APK 依次覆盖原 1.2.2。测试核对首次安装时间、保存的设备、已安装 APK 的 SHA-256，以及从目标写入后在界面显示的新日志标记。ARM 两种 ABI 和 x86 的独立包完成签名和静态验证。RK3566 作为被控真机参与测试，未在其上安装 Android 主控。

Windows 内存是界面就绪 3 秒后采样的进程树工作集之和，两版均为两个进程。Android PSS 来自同一 API 35 模拟器。两者均取三次中位数。JVM 线程数来自同一双设备 Java 工作负载，包含测试驱动线程，未计入原生线程。

固定重放验证全部 24,000 行及 Unicode 标签，按 32 KiB 输入，预热后取三轮中位数。JNI 次数包含打开和关闭。采样堆峰值包含测试输入及解码对象。单次返回量是此输入的观测值，程序另有 256 KiB 硬上限。32 路长日志比较在同一 JVM 参数下填充相同的 1,504 行 × 4 KiB / 路，通过 Windows 私有提交量的填充前后差值估计原生开销。该数值包含分配器和进程运行开销，未做逐次原生分配跟踪。

两版发现测试均返回 5 个候选，每版各一次。自动重连采用同一测试模拟器的地址与端口迁移，以及验证目标标记的用例。另一次 adbd 重启后业务恢复耗时从 6.556 秒变为 17.545 秒，本轮保留了原会话。RK3566 传输对照使用同一 4 MiB 随机数据，分别往返三次并逐字节校验，表中速度来自中位耗时。此次上传和下载均较慢，先前一组短测的上传差异方向相反，单组局域网数据不足以定位瓶颈。

本轮用更多 JNI 分页调用换取了更小的单次分配，专用线程预算也使轻载时的线程数稍有上升。VPN 实际切换、多物理网卡环境、ARM 主控运行和长时间稳定性均未测试。Windows 安装验收采用现有 Windows x64 电脑。可复用的重放和并发驱动位于 [qa/native-core](../qa/native-core)，桌面和 Android 用例位于 [app/src](../app/src)。
